## 照片识图和判题

原手机备份只用于私密读取 AI 配置；未将用户数据库、笔记或卡片复制到虚拟机。图片识别使用原有 `doubao-seed-2-0-lite-260428`，独立简答判题使用 `deepseek-flash`；本次没有擅自替换供应商。密钥不进入源码、测试报告或发布资产。

测试图片包括两幅公开手写图片的白底衍生，以及七幅明确标记的本地合成图、印刷图和空白图。公开来源为 [手写数字 4（RosarioVanTulpe，PD-text）](https://commons.wikimedia.org/wiki/File:Four_handwritten.svg) 与 [手写“上海”（WQL，CC0）](https://commons.wikimedia.org/wiki/File:Handwriting_%E4%B8%8A%E6%B5%B7.svg)。图片不是学生实拍试卷；合成图额外加入印刷参考答案 9 / 北京，验证这些内容不会覆盖手写 4 / 上海。

| 用例 | 实际结果 |
| --- | --- |
| 网上数字 4、中文“上海” | 只提取对应手写内容，正确作答正常通过 |
| 算术正确 / 错误混排 | 只取手写 4；2+2 判对，2+3 判错；印刷参考 9 被排除 |
| 中文正确 / 错误混排 | 只取手写“上海”；Shang hai 判对，Bei jing 判错；印刷参考“北京”被排除 |
| 纯印刷页、空白页 | 无手写答案，保留识别待核对状态，不调用判题 API，不直接判错 |
| 合成手写分数 1/4 | 恢复并显示数字分式，数值判断正确 |

修复后实际九例全部通过，共九次识图、五次 AI 判题，无格式重试；单例约 3.1–10.4 秒，受网络与供应商影响，不作为所有照片的速度承诺。仅这九例不能证明所有复杂字迹都能正确识别。

首轮八例通过、分数例失败的原因是模型 JSON 中单个反斜杠 `\frac` 的 `\f` 被解析成 U+000C。合法 LaTeX 原本可用。本版仅恢复确定的完整数字分式，不推测未知字符、不改分子分母；其他控制字符继续保留疑点并要求核对，零分母也不判为正确。

选图、识图、核对全程纳入任务管理。页面离开、取消或数据库恢复后，旧结果不会继续回填。切换题目时保留题目 Key，并在父页面回填前再次核对会话、题目序号与卡片 ID，防止旧组件尚未销毁时串题。离线测试曾复现帧前串题，修复后覆盖同一窗口与当前题正常回填。

虚拟机进一步发现判题后禁用输入框会展示原始 TeX 与内部照片链接。本版改用公式阅读卡片，原图通过“查看作答照片”按钮打开。原始答案、引用及照片字节继续保存，错误答案也展示本人实际作答。新增回归在 320px、系统两倍字体下验证分式渲染、照片实际加载、内部代码不外露、持久内容不变和未完成 AI 作答继续编辑。

## 大容量备份

个人数据库上限 64 GiB、自定义背景上限 512 MiB。采用受约束的 STORE ZIP32/ZIP64，按块计算 CRC/SHA-256、读取和写出，不一次装入整个备份。入口限制与服务一致，旧有效 `.sparkmemo` / `.bin` / `.db` 仍按内容校验。恢复前完整安全备份、失败回滚和恢复后即时刷新继续保留。

专项检查覆盖 ZIP64 尾记录、64 位长度、局部与中央目录一致性、重复字段、重叠载荷、损坏 CRC、超限拒绝及回滚。在 Windows 的真实 NTFS 稀疏文件上验证超过 4 GiB 的目录偏移和有效 SQLite 头的准备路径；稀疏边界测试未全量读写 4 GiB 载荷。

100 MiB 合成 SQLite 数据库完成创建备份、末字节 CRC 损坏拒绝、恢复和恢复前安全备份验证，约 13.742 秒，采样进程常驻内存增量约 17.3 MiB。此为 Windows 测试进程结果，不能作为 Android 性能承诺。大备份仍需足够剩余存储；64 GiB 为格式和容量上限，不宣称手机完成 64 GiB 全量测试。
