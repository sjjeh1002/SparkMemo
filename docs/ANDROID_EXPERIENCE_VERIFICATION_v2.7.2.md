## 图片、比较方法与计分范围

核心比较为 **17 个任务**，不是 17 张互不相关的实拍试卷：10 个既有公开/合成任务，加上 5 张新网络图片上的 7 个任务。同一图片可分别检查“文档转录”和“只提取本人手写作答”，两者目的不同。补充数学使用另外两张公开实拍原图的裁剪，单独报告，不并入核心比较宣称全面领先。

输入包括公开手写数字与中文、印刷题干和参考答案干扰、空白和纯印刷对照、合成分数、印刷公式、真实中文手写段落、电子笔迹截图、黑板公式、周期表和字帖封面。原图已在本地查看，标注在候选模型调用前独立完成；标准答案、排除词和人工评分规则没有作为答案发送给模型。

每张输入在调用前核对 manifest 中的 SHA-256；有来源、作者、许可、修改方式和人工可见证据。不同可用模型使用同一输入与生产识别器的同类任务提示，`detail=high`、回答上限 8192，比较调用超时设为 90 秒。模型按其服务支持的参数发送请求，协议可兼容不等于推理实现完全相同；记录的 `effort` 字段也不能证明不同服务执行了等量推理。

“通过”指该任务满足事先固定的检查，包括手写存在状态、转录内容、印刷内容排除、公式关键结构及疑点要求。中文段落允许标明的简繁体等价和标点/空格差异，不允许模型润色原文。周期表只核对前 20 个元素中文名等锚点，不代表完整单元格布局和全表校对；字帖只检查清楚的大小写字母及 `1152` 等锚点，不凭模糊的小字判定全部正文。另有一张模糊黑板照片未纳入核心成绩，不能事后挑选模型输出替代标注。

比较脚本只发送经审阅的公开或合成图片，不导入个人卡片/笔记，不写复习日志或 FSRS。HTTP 请求数包含格式重试等实际尝试，不等于图片数，也不等于账单金额；耗时包含网络、服务生成和重试，不能当作手机硬件基准。

本机可追溯文件为 `vision-compare-v272/manifest-base.json`、`manifest-full.json`、`fixtures-new/manifest.json` 和 `fixtures-extra-math/manifest.json`。当前完整 manifest 可包含补充的两个任务；核心表只统计固定的前 17 个任务。原图、逐例原始输出、测试备份和凭据不作为公共 Release 附件。

## 补充真实数学图片：自动检查与人工完整性分开

补充图片分别是 Cornell 教室黑板上的傅里叶系数积分公式，以及白板上的八组方程步骤。均从公开原图做整数坐标裁剪，保存为 PNG；没有补笔画、重绘、清理、旋转或增强图像。裁剪边界、原始文件和裁剪 SHA-256 均在 manifest 留存。

积分核对包括下标 `k`、系数 `2/L`、积分上下限、`f(x)`、正弦参数及 `dx`。白板核对八组、十六行以及八处原有空白，不允许模型补解方程。实际调用使用生产通用文档提示，manifest 中另写的“只取蓝字”人工说明没有单独发送给模型，因此不能把通用提示允许的法语、图标或编号当作违规扣分。

修复文档模式的控制字符问题后，本机 `results-postfix-doh.json` 的六条调用自动关键结构检查 **6 / 6**，但完整正文人工复核为 **5 / 6**。自动锚点命中不能代替完整数学式核对。

| 模型 | 积分公式完整正文人工核对 | 积分用时 | 八组白板步骤人工核对 | 白板用时 | 本轮请求 |
| --- | --- | ---: | --- | ---: | ---: |
| `deepseek-flash` | 未完整通过：可见下限 `0` 写为“待核对” | 24.983 秒 | 通过，16 行与 8 处空白保留，没有补答 | 6.040 秒 | 2 次，各图 1 次 |
| `doubao-seed-2-0-lite-260428` | 通过 | 17.657 秒 | 通过，16 行与 8 处空白保留，没有补答 | 29.840 秒 | 2 次，各图 1 次 |
| `doubao-seed-2-1-lite-260915` | 通过 | 50.797 秒 | 通过，16 行与 8 处空白保留，没有补答 | 41.576 秒 | 2 次，各图 1 次 |

因此补充两例的完整正文人工结果分别为 Flash **1 / 2**、Lite 2.0 **2 / 2**、Lite 2.1 **2 / 2**。豆包 2.0 额外把整条公式列为一个 `figures` 图元，是冗余结构；本表按数学正文核对，没有据此扣除已正确转录的正文。六条最终调用均未出现坏控制字符，且各只有一次请求。

Flash 对积分下限保留疑点，符合不猜写的安全方向，但仍未达到完整转录要求，不能计成通过。复杂公式仍应查看原图核对上下限和下标；本轮补充样本不证明任一模型能可靠识别所有教材公式。

补充检查曾发现：模型 JSON 把数学命令中的单个反斜杠转为控制字符，文档模式仍可能将损坏文字保存为成功。当前源码为文档结果增加控制字符验证；可进行一次格式修复，连续不合格则明确失败，不能猜回未知命令。既有确定数字分式的安全恢复保留，合法数学命令及普通空白不因此被错误拒绝。离线定向测试覆盖损坏、修复上限和合法符号；最终完整测试结果只以上方最终事实为准。

## 默认识图来源、旧设置保留和异常反馈

当前源码提供“自动推荐”“独立识图接口”和“跟随已有 DeepSeek”三种来源。自动推荐优先使用用户已经配置且符合明确识图型号、官方 HTTPS 域名及路径要求的 DeepSeek；依次检查 AI 助手、出题与判题配置。没有可用跟随项时使用已有独立识图配置，并在页面显示实际来源和回退原因；完全没有凭据时明确提示未配置，不附带任何共享密钥。

旧版本未保存来源键、且参数恰为内置豆包 Lite 2.0 默认预设时，读取为自动推荐。已有明确选择的独立模式、其他模型、第三方接口或自定义参数不会因为名称相似被当成默认项覆盖。读取设置本身不写入迁移值；用户切换来源也保留独立接口的地址、模型和密钥，不在供应商之间复制凭据，不擅自改变独立的出题/判题配置。

只凭 `deepseek` 名称或 OpenAI 兼容协议不认定识图可用；不向任意中转域名发送已有 DeepSeek 密钥。无法读取的原密钥与“没有设置密钥”分开处理：即使当前有效的 DeepSeek 路由可用，损坏但未使用的独立密钥仍保留并提示；不能用空白保存覆盖该记录，需用户明确重新填写。页面显示独立参数供核对，不把读取失败伪装成空白默认值。

照片作答和批量资料入口都接收相同的配置异常，显示可处理的安全说明；没有可跟随配置时不会先打开选图器，批量资料中已保存的原页仍保留。识图提示明确电子笔迹和印刷仿手写范字的区别，但未因此宣称所有混排图片都能自动判断正确。照片仍先识别、用户核对再填入；无法可靠确认时不直接写入学习评分或 FSRS。

这些行为已分别纳入路由/配置保留定向测试，以及使用真实内存 SQLite 的两项入口错误反馈 widget 回归。它们证明离线控制路径，不替代最终 APK 与真实模型在手机上的全部验收。

## 助手界面与笔记恢复竞态

助手原布局在 320×700、两倍字号、键盘高度 280 且附有三篇笔记时，曾复现底部 `RenderFlex` 溢出 38px。附件现改为一行横向查看、长标题省略，输入框根据可用高度和字号限制为 1–4 行；这些只是显示限制，草稿与已附加的正文快照不因布局再次截断。原有单篇最多 24000 字符及长笔记范围确认规则仍保留，未宣称整本笔记必定全文发送。

另在 740×360 横屏、1.6 倍字号、键盘高度 140 时，让真实助手页面的模拟 completion 抛出异常，原固定错误区把消息列表压到 **2px**。错误及读取重试区改为消息滚动列表的一部分后，同一夹具消息区为 **90px**，可滚动查看错误并点击“继续未完成的回复”。该夹具没有直接触发新的 `RenderFlex` 异常，不能将消息区被挤没误写为已观测到的溢出错误。

新增失败→继续流程验证：原两行草稿和三篇附件的完整正文进入原用户消息，失败记录保留；继续时使用同一份历史，不重新追加用户消息或重复发送一个新的用户轮次。数据中只有一条用户记录，恢复后的回复正常保存。另覆盖 320 宽、2 倍/2.6 倍字号和横屏键盘下的正常发送、三附件及按钮可触达。

笔记原删除确认框在数据库恢复锁开启或数据库换代后，仍可能调用旧 repository，把笔记与来源卡片软删除；旧页面也能打开过期资料详情。打开入口及等待后的恢复锁/代次校验现阻止这些操作。回归分别验证恢复锁、换代、旧页面打开/删除均被拦截，以及正常确认删除仍将笔记和来源卡片放入回收站，没有靠禁用全部删除来通过测试。

上述均使用合成资料与真实内存 SQLite；没有读取或删除用户个人笔记。助手任务退出取消、多会话持久化、笔记导入返回导航及附件范围沿用既有检查。阶段性定向回归与最终全套测试必须分开阅读，不把某组专项通过替代顶部最终结果。

## 测试网络、TLS 纠正及已披露风险

本机最初的系统解析/连接问题没有 HTTP 识图结果，只能记录为网络失败，不能算作豆包模型识图差。后续比较对 Ark 仅在显式开启的本地测试进程使用 Google HTTPS DoH 查询得到的短 TTL 地址；没有修改系统 DNS、hosts、代理、服务、证书信任或产品网络配置，不把这次地址写入 Android 默认配置。

本地比较脚本曾有一次错误的临时连接适配：将裸 TCP socket 返回给 HTTPS 的 `connectionFactory`，存在未加密发送请求及暴露凭据的风险。发现后已终止该指定测试进程及子进程，并向用户说明。该尝试没有完成任何用例记录，不计模型比较成绩；**没有完成结果不能保证请求未发送，也不能保证凭据未暴露**。已建议在测试结束后轮换本次使用的 DeepSeek 和豆包两套 API 密钥，未擅自轮换而中断用户手机配置。

后续连接已改为等待 `SecureSocket.secure` 完成，使用原始 HTTPS 域名作为 host/SNI，保留默认信任库与证书验证，再将连接交给 HTTP 客户端；没有证书放行回调或关闭验证。独立无凭据复核在合法域名取得 HTTP 401 和对应 Ark 域名证书。故意错误主机名在发送 HTTP 头前被握手拒绝，但实际错误是服务端提前结束握手，不能仅凭该负向响应声称已实测到客户端 `CERTIFICATE_VERIFY_FAILED`；保留客户端校验的结论也依赖静态代码审阅。

本地 Dart 诊断适配对 IPv4 输入的独立检查只排除回环，没有完整实现私网/fake-IP 分类；实际候选地址由调用脚本的公网地址筛选与公共 DoH 得到，并继续做原域名 TLS 验证。本次诊断不是可直接上线的通用 DNS 代理。明细在本机 `network/TRANSPORT_CORRECTION.md`、`TLS_REVIEW.md` 和相应无凭据 JSON，短 TTL 地址不能永久固定使用。

这一适配仅存在于明确启用的手动比较测试，未进入生产识图客户端或 APK 网络策略。API 密钥仅私密进入测试子进程内存，没有写入源码、命令行、逐例报告或发布附件；这不抵消前述临时连接错误的潜在网络暴露风险。

## 最终设备、数据与交付边界

Android 后续验证使用独立 `SparkMemo_API36` 虚拟机、固定 `emulator-5554`，仅使用公开图片和合成卡片/笔记。经用户明确授权，只从已校验的手机备份私密读取原有 AI 设置；不把用户真实数据库或整份备份导入虚拟机，密钥不进入公共材料。

本轮最终公开 APK/开发 APK 的构建、签名、加固、文件指纹、覆盖安装和实际界面结果，必须逐项写入顶部最终事实；当前文档不以旧版 APK 的设备验收或已开始的构建替代完成结果。公开包的设备结果也不代表开发包或全部机型验收。网络图片可检查图片输入、识别与核对流程，不能替代物理摄像头、真人不同字迹和厂商文件提供器测试。

64 GiB 个人库/512 MiB 背景、ZIP64 流式备份和恢复前安全备份是已有功能；本版没有据此声称完成手机 64 GiB 全量读写。包含 AI 配置和会话的个人备份继续私密保存。
