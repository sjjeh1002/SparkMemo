# v2.5.1 草稿分页与隔离修复

2026-09-26；应用 2.5.1+21，SQLite v9。延续 v2.5.0 的记忆期限、多级目录和数学输入，不改变 FSRS-6 参数、评分或清单覆盖算法。

## 本轮实现

- 打开草稿不再一次解析全部生成结果。页面从 SQL 读取 50 张卡片、30 条分段摘要；展开才读取该段原文和知识点映射，折叠释放详情。失败原因、部分覆盖及未覆盖数量仍明确显示，不以隐藏警告代替修复。
- 导入每批 100 张，整次导入使用同一事务。后续批次失败会回滚此前批次和知识点写入。无论当前预览在哪一页，导入的都是整份草稿；同一笔记中已有同题同答案不重复导入，也不自动复活已删除卡。
- 预览去重保持原有规则：跨段相同题干保留首次出现的卡片。修改某段后源检查点、摘要及卡片索引一起提交，不留下新旧混杂的状态。
- 修复任务 ID 仅使用时间戳导致的撞号风险：新 ID 带 128 位安全随机后缀，旧 ID 可原样恢复；写入时在事务中检查任务所属笔记，禁止另一篇笔记覆盖它。
- 批量修改草稿记忆期限、目录或卡组只更新任务元数据，不重新序列化全部卡片；保存失败保持原设置。卡组修改现在会持久化。
- 修复分段展开的 Future/setState 问题，异步失败及时捕获并显示可重试入口。

## 数据迁移

v8 → v9 只添加 generation_segments 的 summary_json / completed / planned_cards、派生表 generation_preview_cards 及查询索引。学习卡片内容、FSRS、历史、笔记和设置不重写。

旧行式草稿在首次打开时逐段补建派生索引；升级数据库本身不解析草稿，损坏的旧草稿不会阻断数据库升级。源 JSON 保留不变，补建中断可继续。更旧的 settings 整块草稿仍需一次性读取后转换，不宣称它已有流式迁移。派生索引额外占用磁盘空间，用空间换取分页读取。

降级前须恢复旧版数据库备份；不要用 v2.5.0 直接打开 v9 数据库。
